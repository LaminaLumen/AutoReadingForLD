# 开发与验证

## 环境要求

- Node.js 18 或更高版本；
- Tampermonkey、Violentmonkey 或 ScriptCat；
- 支持 Shadow DOM、Pointer Events、`requestAnimationFrame`、WebGL 1.0 和 CSS `color-mix()` 的现代浏览器；WebGL 不可用时胶囊材质自动降级为 CSS 渐变。

项目没有生产依赖，也不需要打包。根目录下的 `Lanyue.user.js` 始终是可以直接安装的发布文件。

## 本地检查

在项目根目录执行：

```powershell
npm run check
```

检查脚本会验证：

- JavaScript 语法是否有效；
- 用户脚本元数据是否完整；
- 元数据版本、运行时版本与 `package.json` 是否一致；
- 匹配范围是否仅限 LINUX DO 帖子页和四个受支持的列表入口；
- 是否保持 `@grant none`；
- 是否意外引入跨域权限、远程依赖、网络请求、动态执行或全量清空本地存储。

## 人工验证清单

### 基础功能

1. 在 `/t/` 普通帖子打开页面，确认右侧显示最小化入口。
2. 在“当前帖”模式启动滚动，确认进度、用时和行程更新，到底后停止。
3. 滚动期间让 Discourse 将地址更新为带楼层号的 `/t/<slug>/<topic-id>/<post-number>`，确认当前帖不会被重置或暂停。
4. 修改平均速度，确认滚动节奏存在缓慢的小幅变化；刷新页面后设置仍被保留。
5. 分别在 100%、125% 和 150% 页面缩放下抽样 5–10 秒，确认实际平均位移与速度设置相符，不因高 DPI 像素量化明显加速。
6. 使用 `Alt + S`、`Alt + ↑`、`Alt + ↓` 和 `Alt + M`。
7. 在回复编辑器中输入快捷键，确认脚本不拦截。

### 阅读模式与队列

1. 切换到“自动帖”，手动打开另一个帖子，确认正文就绪后自动开始并在末尾停止。
2. 分别在 `/new`、`/unread`、`/unseen` 和 `/latest` 验证“连续读”；只有已加载、带站点未看/未读标记且未访问过的帖子入队，已访问旧帖即使有新回复也要排除。
3. 调整“队列容量”和“本轮上限”；首次建立队列后确认默认补到 10 篇，且已收集总数不超过本轮上限。
4. 每篇完成后确认前台冷却 8 秒；切换到后台不应消耗冷却时间。
5. 确认队列通过同源链接在同一标签页切换，Discourse 单页路由可正常接管；刷新后可以恢复，偏离队列时会停止。
6. 将队列推进到剩余约 2 篇，确认返回原列表并通过原生列表加载哨兵补满，已经收集过的话题不得再次加入；刷新补队列页面后仍可继续。
7. 将本轮上限设为 20，确认第 20 篇后完成；列表没有新帖时，应先读完剩余篇目再完成，并返回原列表。点击“停止连续阅读”后不再跳转。
8. 分别使用 6、18、42、80 层的帖子，确认控制台显示的最低时长随楼层数递增。
9. 在 6 层帖子使用最高速度，确认不会早于计划时间完成；使用默认速度阅读较长帖子，确认脚本只会限速而不会强制提速。
10. 在 `/t/topic/1097` 超长帖夹具设置 160 像素/秒并启用连续读，确认未加载完整篇时实际速度接近设置值，不被 7545 层的最低时长压到爬行。
11. 阅读中暂停数秒后继续，确认暂停时间不计入剩余计划；在懒加载后把楼层数从 6 增加到 42，确认计划只会上调。
12. 至少完整运行两篇队列，确认首篇满足计划和末尾等待后进入冷却，冷却结束再自动进入下一篇。

### 懒加载

1. 选择回复较多的长帖。
2. 在 `/t/topic/1098` 分批夹具或真实 Discourse 长帖启动任一模式，确认隐藏加载哨兵在已加载末楼进入视口前就请求下一批；站点每批数量仍由自身控制。
3. 新楼层加载后确认滚动继续，不回跳到后续楼层；已加载末楼还存在加载哨兵时显示“载入”，不进入“完成”。
4. 在 `/t/topic/1096` 停滞夹具验证：超过原有 6 秒等待仍不得误判完成；持续加载超时后停在当前帖并显示原因。
5. 原生正文流出现真正末楼后，再等待末尾稳定约 6 秒；连续读还必须同时满足当前楼层计划。

### 阅读记录与蓝点恢复

1. 在真实 Discourse 页面确认未读楼层使用 `.read-state:not(.read)`，已读楼层使用 `.read-state.read` 并被站点样式隐藏。
2. 使用较高速度让未读楼层接近视口上缘，确认滚动中已消失的蓝点不会造成额外停顿；仍未消失时状态显示“正在确认 X–Y 层”，蓝点消失后继续而不进入“已暂停”。
3. 到达末尾时，确认可见未读楼层会阻止完成/切帖；蓝点消失并稳定 0.9 秒后才完成。
4. 在本地预览页使用 `?reportDelay=3600` 模拟延迟记录，确认逐视窗等待和正常续滚均生效。
5. 使用 `?postOffset=900&report=backoff&reportDelay=45000` 模拟高楼层单楼延迟消点：短暂初始等待后仍守住该楼层，约 45 秒后蓝点消失并续滚，不发生提前重载。
6. 使用 `?postOffset=900&report=rate-limit&retryDelay=30000` 模拟站点原生 HTTP 429 后 200：429 时必须显示“站点限流”，滚动位移保持 0；200 与蓝点消失后自动续滚，并显示暂缓后的速度上限。夹具中的请求由页面自身发出，用户脚本不得发送。
7. 使用 `?postOffset=900&report=rate-limit-stuck&retryDelay=30000` 模拟持续 429：不得重载当前帖或越过蓝点；达到最多 10 分钟的限流等待上限后停在当前帖并停止连续队列。
8. 使用 `?report=stuck` 模拟蓝点永不消失但无 429：先发生 `1px` 原生微滚动，再等待最多 120 秒；之后只完整重载当前楼层一次，目标楼层实际渲染后才恢复，再失败时停在当前帖。
9. 在“连续读”模式重复上述失败测试，确认队列被停止，不会进入下一帖，也不会形成重载循环。
10. 在真实站点检查网络面板：`/topics/timings` 必须始终由 Discourse 自身发起，脚本不得直接调用、代理或伪造该接口；记录卡住时区分 429、5xx、200 和无请求。

### 页面与主题

1. 分别测试 `/t/`、`/n/` 视图与四个受支持的列表入口。
2. 通过站内单页导航进入和离开帖子，确认控制台正确显示或隐藏。
3. 切换亮色与暗色主题，确认面板背景、文字、边线和强调色同步变化；将 `body` 设为透明背景时也不得误判为暗色。
4. 将窗口缩窄至移动端宽度，确认面板不会超出视口。
5. 收起后确认快捷胶囊能区分就绪、阅读中、等待、暂停和完成；点击 `148 × 48px` 胶囊主区可开始、暂停和继续，点击右侧参数按钮只展开设置。
6. 在四个象限分别展开，确认方向依次为右下、左下、右上和左上，对应角在视口允许时保持原位。
7. 从胶囊主区拖动入口，确认移动不会误触发开始或暂停；分别拖到左上、右上、左下和右下象限以及视口四条边的极限位置，确认入口完整可见，展开后面板自动回到 `12px` 安全边距内。
8. 确认 WebGL 水纹只在收起且阅读活跃或悬停时动态运行；切换暗色主题、后台标签页与系统“减少动态效果”后，颜色和动画策略正确；禁用 WebGL 时仍有 CSS 降级材质。
9. 快速连续执行展开、收起和位置复位，确认没有上一帧定位覆盖新操作，也没有明显跳变。

### 暂停规则

1. 确认后台暂停与手动操作暂停首次安装时均为关闭状态。
2. 开启后台暂停后切换标签页，确认自动暂停；返回原帖子后应自动继续。
3. 开启手动操作暂停后使用滚轮、触摸或翻页键，确认自动暂停；刚点击开始后的触控板惯性事件不应立即触发。
4. 在控制台内部拖动滑块或面板，确认不会错误触发手动暂停。
5. 重载恢复期间切换到后台再返回，确认仍只有一次重载，不因页面可见性变化重复恢复。

## 版本更新

发布新版本时需要同时修改：

1. `Lanyue.user.js` 元数据中的 `@version`；
2. 脚本中的 `APP.version`；
3. `package.json` 的 `version`；
4. `CHANGELOG.md`。

随后执行 `npm run check`，确保版本一致。

## 工程约束

- 不引入构建步骤，保证仓库源码即发布内容。
- 不使用远程 `@require` 或第三方网络接口。
- 连续切帖只能由用户明确启用的有界队列触发，不扩大到自动互动、随机点击、无限遍历或账号数据查询。
- 队列中的帖子地址和返回列表地址必须保持同源，恢复本地数据时也必须重新校验。
- 新增存储项时必须限定明确的命名空间，不得调用 `localStorage.clear()`。
- 时间相关逻辑使用 `performance.now()` 计算时长，不按帧数推算秒数。
- 面向用户的时间语义按浏览器本地时区展示；脚本当前不写入日志时间戳或远端数据。

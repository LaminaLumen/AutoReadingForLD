# 开发与验证

## 环境要求

- Node.js 18 或更高版本；
- Tampermonkey、Violentmonkey 或 ScriptCat；
- 支持 Shadow DOM、Pointer Events、`requestAnimationFrame` 和 CSS `color-mix()` 的现代浏览器。

项目没有生产依赖，也不需要打包。根目录下的 `AutoReadingForLD.user.js` 始终是可以直接安装的发布文件。

## 本地检查

在项目根目录执行：

```powershell
npm run check
```

检查脚本会验证：

- JavaScript 语法是否有效；
- 用户脚本元数据是否完整；
- 元数据版本、运行时版本与 `package.json` 是否一致；
- 匹配范围是否仅限 LINUX DO 帖子页和四个受支持的列表入口；
- 是否保持 `@grant none`；
- 是否意外引入跨域权限、远程依赖、网络请求、动态执行或全量清空本地存储。

## 人工验证清单

### 基础功能

1. 在 `/t/` 普通帖子打开页面，确认右侧显示最小化入口。
2. 在“当前帖”模式启动滚动，确认进度、用时和行程更新，到底后停止。
3. 修改平均速度，确认滚动节奏存在缓慢的小幅变化；刷新页面后设置仍被保留。
4. 使用 `Alt + S`、`Alt + ↑`、`Alt + ↓` 和 `Alt + M`。
5. 在回复编辑器中输入快捷键，确认脚本不拦截。

### 阅读模式与队列

1. 切换到“自动帖”，手动打开另一个帖子，确认正文就绪后自动开始并在末尾停止。
2. 分别在 `/new`、`/unread`、`/unseen` 和 `/latest` 验证“连续读”；列表只使用页面中已加载的符合条件帖子。
3. 调整队列上限，建立队列后确认篇数没有超过设置值，且帖子按列表顺序处理。
4. 每篇完成后确认前台冷却 8 秒；切换到后台不应消耗冷却时间。
5. 确认队列在同一标签页切换，刷新后可以恢复，偏离队列时会停止。
6. 完成全部条目后确认返回原列表；点击“停止连续阅读”后不再跳转。

### 懒加载

1. 选择回复较多的长帖。
2. 自动滚动至当前页面底部。
3. 确认脚本进入“等待”状态，而不是立即结束。
4. 新楼层加载后确认滚动继续。
5. 页面高度稳定约 6 秒后确认状态变为“完成”。

### 页面与主题

1. 分别测试 `/t/`、`/n/` 视图与四个受支持的列表入口。
2. 通过站内单页导航进入和离开帖子，确认控制台正确显示或隐藏。
3. 切换亮色与暗色主题，确认面板背景、文字、边线和强调色同步变化；将 `body` 设为透明背景时也不得误判为暗色。
4. 将窗口缩窄至移动端宽度，确认面板不会超出视口。
5. 收起后确认状态胶囊能区分待机、阅读中、等待、暂停和完成，并将 `116 × 44px` 入口分别拖到左上、右上、左下和右下象限，确认入口不会为完整面板预留活动区域。
6. 在四个象限分别展开，确认方向依次为右下、左下、右上和左上，对应角在视口允许时保持原位。
7. 将收起入口拖至视口四条边的极限位置，确认入口自身完整可见；展开后确认面板自动回到 `12px` 安全边距内。
8. 快速连续执行展开、收起和位置复位，确认没有上一帧定位覆盖新操作，也没有明显跳变。

### 暂停规则

1. 开启后台暂停后切换标签页，确认自动暂停。
2. 开启手动操作暂停后使用滚轮、触摸或翻页键，确认自动暂停。
3. 在控制台内部拖动滑块或面板，确认不会错误触发手动暂停。

## 版本更新

发布新版本时需要同时修改：

1. `AutoReadingForLD.user.js` 元数据中的 `@version`；
2. 脚本中的 `APP.version`；
3. `package.json` 的 `version`；
4. `CHANGELOG.md`。

随后执行 `npm run check`，确保版本一致。

## 工程约束

- 不引入构建步骤，保证仓库源码即发布内容。
- 不使用远程 `@require` 或第三方网络接口。
- 连续切帖只能由用户明确启用的有界队列触发，不扩大到自动互动、随机点击、无限遍历或账号数据查询。
- 队列中的帖子地址和返回列表地址必须保持同源，恢复本地数据时也必须重新校验。
- 新增存储项时必须限定明确的命名空间，不得调用 `localStorage.clear()`。
- 时间相关逻辑使用 `performance.now()` 计算时长，不按帧数推算秒数。
- 面向用户的时间语义按浏览器本地时区展示；脚本当前不写入日志时间戳或远端数据。
